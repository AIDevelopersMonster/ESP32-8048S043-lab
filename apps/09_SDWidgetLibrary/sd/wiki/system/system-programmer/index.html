Boot order

NVS credentials, internal storage, Widget Runtime and OTA initialize first. SD manager initializes without mandatory boot-time mount. Network stack and services start before the display shell and HTTP server. A missing SD card must not block SYS/recovery or the persisted widget.

SD manager

Current physical mapping: CS GPIO10, MOSI GPIO11, CLK GPIO12, MISO GPIO13. Initial validated SPI frequency is 10 MHz. Automatic formatting is disabled.

Web Help

The HTTP layer exposes four exact Help handlers: /help, /help/system, /help/app and /help/style.css. The handler mounts SD on demand if necessary. The landing page scans package manifests and exposes only packages declaring documentation.entry = html/index.html.

Serial service 0.3.5

Platform 0.3.5 adds the generic serial service used by the SD package usb-serial-terminal. Stage 1 deliberately reuses the existing UART0 console path instead of independently reinitializing the UART driver:

PC <-> USB <-> CH340C <-> UART0 <-> serial_service <-> Widget Runtime

The service publishes serial.rx_text, serial.rx_bytes, serial.tx_bytes and serial.state, plus the actions serial_send_test and serial_clear. Because UART0 is also the ESP-IDF console, normal log output is expected on the same PC terminal.

Sample A, 2026-09-22: the onboard USB-UART route was physically exercised in both directions. This acceptance does not extend to P1 application-UART use.

Security

SD HTML is untrusted content relative to platform control APIs. Help responses therefore disable script execution, forms, frames, objects and fetch/connect through Content Security Policy. File paths are not supplied directly by the browser: system pages use a fixed allow-list and package names use the same restricted ASCII directory rule as SD Manager.

Firmware update rule

Application-specific functionality stays on SD whenever existing services and capabilities are sufficient. Platform firmware changes only for a genuinely reusable capability, provider, driver, runtime primitive or security/recovery change.

Known current limits

  • manifest requirements such as minimum_platform and requires.services are not yet enforced by SD Manager;
  • catalog limit is currently 24 entrypoints;
  • entry file names are direct basenames;
  • offline /UPDATE full flash-write path remains an acceptance item;
  • the App09 display source is still generated by CMake from the proven App08 renderer;
  • generic textarea and keyboard Widget Runtime primitives are not yet implemented.

Version boundary

Platform 0.3.3 introduced browser-only SD Help. Platform 0.3.5 adds the reusable serial service consumed by USB Serial Terminal. No long-form Help UI is added to the 800x480 display.
