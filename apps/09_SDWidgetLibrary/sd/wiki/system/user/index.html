1. Что это

KONTAKTS Platform — прошивка для ESP32-8048S043 с тремя основными областями на дисплее: SYS | SD | WIDGET. Приложения могут храниться на SD и запускаться через Widget Runtime.

2. Прошивка с Windows

Для полного BIN используйте вспомогательный ESP32 BIN Flasher v2 из репозитория. Для нашей платы выбран ESP32-S3, адрес полного образа обычно 0x0. Загрузчик не выполняет erase-flash автоматически.

python -m esptool --chip esp32s3 --port COMxx --baud 921600 write-flash 0x0 firmware.bin

3. Wi-Fi

После первого запуска платформа поднимает setup AP, если сохранённых параметров сети нет. После подключения к домашней сети IP платы отображается в SYS и используется для web-интерфейса.

4. SD-приложения

SD:\widgets\youtube\
SD:\widgets\clock\
SD:\widgets\youtube-led\
SD:\widgets\weather\
SD:\widgets\usb-serial-terminal\

Скопируйте совместимый пакет в widgets, вставьте SD и нажмите REFRESH на вкладке SD. Платформа читает package.json и строит каталог автоматически.

5. USB Serial Terminal

Начиная с платформы 0.3.5, пакет USB Serial Terminal использует штатный USB-разъём платы и onboard CH340C для связи с UART0 на 115200 8N1. Входящий текст с PC показывается на TFT, а кнопка SEND TEST отправляет на PC строку KONTAKTS USB SERIAL TEST.

Для Windows можно использовать наш терминал KONTAKTSerial из tools/KONTAKTSerial:

python -m pip install pyserial
python .\tools\KONTAKTSerial\KONTAKTSerial.py --port COMxx --baud 115200

PHYSICAL PASS, Sample A, 2026-09-22: USB-UART тракт через CH340C проверен в обе стороны. P1 позже также был физически подтверждён как технологический/service UART0 и вход питания +5 V; он не считается пользовательским полевым UART.

Interactive Serial Terminal

Начиная с Platform 0.3.7, отдельный SD-пакет Interactive Serial Terminal добавляет ввод прямо на TFT: поле textarea, стандартную экранную LVGL 9 keyboard и кнопку SEND. Сам экран терминала хранится на SD; прошивка предоставляет только универсальные UI primitives и serial action.

Текущая LAB-02 версия отправляет набранный текст с окончанием CRLF. История команд, выбор line ending и HEX относятся к следующему этапу.

6. Справка

С телефона или компьютера откройте http://IP-ПЛАТЫ/help. Экран ESP32 для длинной документации не используется. Пакеты, у которых в manifest есть documentation.entry, получают собственную карточку справки автоматически.

7. OTA и восстановление

GitHub OTA, CONFIRM, ROLLBACK и FACTORY RECOVERY находятся в SYS. Не отключайте питание во время записи новой прошивки. После OTA новая версия должна пройти обычный цикл подтверждения.

8. Управление MA01: HMI, Web, UART0 и BLE

Platform 0.3.9 использует единый command/service layer. Одна и та же команда может прийти с экрана, из браузера, через технологический UART0/P1 или по BLE; логика Modbus остаётся внутри MA01 provider.

Web: после подключения к роутеру откройте http://IP-ПЛАТЫ/ma01. Состояние реле связано с HMI.

Технологический UART0: 115200 8N1, удобно использовать KONTAKTSerial 0.3.1. P1 относится к service/debug интерфейсу, а не к полевому Modbus.

BLE: устройство рекламируется как KONTAKTS-8048. Сервис FFF0, команда FFF1 WRITE, ответ FFF2 READ. Подключиться можно как с телефона, так и с компьютера любым BLE GATT-клиентом. Pairing в системных настройках для лабораторного MVP не требуется.

KONTAKTS-8048
Service  FFF0
Write    FFF1
Read     FFF2

MA01 READ
MA01 DO1 INFO
MA01 DO1 ACTION
MA01 DO1 ON
MA01 DO1 OFF

После записи команды в FFF1 прочитайте FFF2. Текущая версия поддерживает одно BLE-соединение одновременно.

9. Platform 0.3.9 — физически проверенная совместная работа

PHYSICAL PASS, Sample A, 2026-09-29: одновременно проверены дисплей/GT911, SD, MA01 через UART1/RS485, Web, Wi-Fi STA/AP, технологический UART0/P1, GitHub OTA CHECK и BLE. Для первого полного запуска через Web Flasher используйте опубликованный full image версии 0.3.9; SD Help обновляется отдельным SD Library bundle.

10. Что сейчас ещё проверяется

  • явное извлечение SD после запуска и работа сохранённого widget;
  • перезагрузка без SD с восстановлением сохранённого widget;
  • полный offline update из /SD/UPDATE.

Отсутствие SD не должно лишать пользователя SYS/recovery. Это архитектурный инвариант проекта.
