The slider does not always acquire the finger immediately. The operator must hit the effective capture area fairly precisely before drag begins. Once accustomed to that target area, the UI is usable and otherwise behaves well.

This is recorded as a **slider hit-target / interaction usability limitation**, not as a display-pipeline failure. It should be addressed separately after the controlled display experiments, because changing slider geometry or touch-target behavior now would introduce an additional experimental variable.

The current serial excerpt contains no touch presses (`press=0`, `release=0`), so the qualitative slider report is operator-observed physical evidence rather than evidence from that particular serial excerpt.

## Interpretation

- no reset/crash observed;
- free heap remains stable;
- free PSRAM remains stable;
- `flush` remains fixed at `24` while the UI is idle, confirming no periodic whole-screen redraw is being generated by this LVGL event-driven path;
- disabling the Arduino_GFX RGB bounce buffer does not prevent successful initialization or stable idle runtime;
- no periodic flicker or recurring horizontal jump is visible with bounce buffering disabled.

The importance of Test 22 is **isolation, not discovery of a newly stable architecture**. Other earlier validated paths had already shown stable operation without the old visible defect. Test 22 makes the comparison stricter by taking the verified Test 19 path and changing only the RGB bounce-buffer setting.

Therefore the controlled pair is now:

```text
Test 19: INTERNAL SRAM + PARTIAL + Arduino_GFX + bounce20 -> PASS
Test 22: INTERNAL SRAM + PARTIAL + Arduino_GFX + bounce0  -> PASS
```

This excludes the 20-line Arduino_GFX RGB bounce buffer as a necessary condition for visual stability in this architecture on the tested specimen.

## Historical numbering note

Test 18 was an LVGL 8 controlled experiment and did not reach comparable physical validation in the current LVGL 9 environment because it was intentionally blocked by its LVGL8-only compile guard. Therefore any operator recollection that Test 22 looks like an earlier stable test should not be attributed to Test 18 as a formally validated A/B predecessor. Test 19 is the controlled physical-PASS baseline for Test 22.
